Full-stack OOP AutoGrader (EIU Capstone) — architecture, services, entry points, and grading pipeline

You have a full-stack academic autograder: students upload Java source and Mermaid class diagrams; the backend compiles Java at runtime, grades against a lecturer-defined rubric in PostgreSQL, and returns instant scores. Lecturers author rubrics, monitor rosters, and view analytics. Everything durable lives in the database; upload files on disk are ephemeral.

What the system can do

ActorCapabilities
Student Login (Google @eiu.edu.vn or IRN+password), pick a lab, drag-drop a folder of challenge_N/ subfolders, get per-challenge scores with Class / MMD / Testcase tabs, view submission history.
Lecturer Create labs and rubrics (classes, fields, methods, constructors, relations, operational testcases), manage users, view grade matrices, lab statistics, at-risk students, analytics dashboards.
Backend engine Compile student Java via javax.tools.JavaCompiler, grade with reflection + MMD parsing + runtime testcase invocation, persist element-level results, assemble an upload-time lab_result JSON bundle for the UI.

How you start it

From the repo root, npm start runs both tiers concurrently via concurrently:

// package.json
"start": "concurrently \"npm run backend\" \"npm run frontend\""
"backend": "cd backend && mvn spring-boot:run"   // → :8002
"frontend": "cd frontend && npm run dev"       // → :5173

Frontend prerequisites

Node.js, frontend/.env with VITE_GOOGLE_CLIENT_ID and VITE_API_URL (default http://localhost:8002).

Backend prerequisites

JDK 17+ (not JRE — needed to compile student code), Maven, PostgreSQL via backend/.env (SPRING_DATASOURCE_URL, credentials).

Architecture at a glance

Communication pattern: no Vite proxy — the SPA calls the backend directly with fetch and a Bearer JWT. CORS is configured in CorsConfig for /api/**. Spring Security permits all requests at the filter level; JWT is checked manually in controllers that need it.

The grading pipeline — heart of the system

When a student uploads, SubmissionController orchestrates compile → grade → persist → respond. This is the most important flow to understand.

Three-pillar scoring model

Each challenge is scored across up to three equal pillars. Challenge score = arithmetic mean of applicable pillar percentages. Lab score = mean across all rubric challenges (missing = 0%).

PillarTechniqueKey classes
Class (Declaration) Compile .java → load .class via URLClassLoader → reflect fields, methods, constructors against rubric. Partial credit per attribute. JavaCompilerService, ReflectionClassParser, ClassReflectionGrader, PartialCreditEvaluator
MMD (Diagram) Parse Mermaid class diagram text in memory; compare classes, members, relations to rubric. Relations are MMD-only. MmdParser, MmdComparisonService, MmdPillarGrader
Operational Testcase Invoke student code via reflection (Constructor.newInstance / Method.invoke); assert return value, stdout, field state, exceptions. Single-thread executor prevents stdout races. InvocationRunner, AssertionEvaluator, TestcaseGrader
Executor split matters: compileExecutor compiles challenges in parallel; gradingExecutor grades challenges in parallel; pillarExecutor runs MMD + testcase pillars inside a challenge; testcaseInvokeExecutor is single-threaded so student System.out capture stays clean.

What persists vs what disappears

  • PostgreSQL: users, rubric structure, lab_submission, per-element submission_*_result rows, student_lab_progress
  • Side JSON files (under submissions/_compile_errors/, _mmd_meta/, _parsed_snapshot/): survive for UI display when present
  • Deleted after grading: temp upload folder, compiled .class files, staged .java sources

Database — the rubric graph

Schema is managed externally (SQL scripts in docs/sql/, no Flyway in the app). The rubric is a tree:

Lab → Challenge → ClassEntity → Field / Method / Constructor
                 → ClassRelation (MMD)
                 → Testcase → Invocation / Instance → Assertion

A lab submission is keyed by (user_id, lab_id, attempt_number). Re-uploading the same attempt updates scores in place rather than creating a new row.

Auth and security

  • Google OAuth restricted to @eiu.edu.vn via GoogleTokenVerifier
  • JWT created by JwtService — signing key is in-memory, so tokens invalidate on server restart
  • Claims: email, name, roles, irn
  • Upload requires a student IRN; lecturers cannot submit

Mental model — one sentence per layer

  • React SPA — authenticates, uploads folders, renders scores from API JSON and cached session state.
  • Spring Boot — owns auth, rubric CRUD, the compile+grade pipeline, and analytics aggregation.
  • Grading engine — turns compiled bytecode + diagram text + testcase rubric into element-level pass/fail and pillar percentages.
  • PostgreSQL — single source of truth for everything that must survive a server restart.

The critical path you will debug most often: browser upload → SubmissionController → SubmissionStorageService (compile) → GradingService (three pillars) → JPA save → lab_result JSON → React tabs update.
